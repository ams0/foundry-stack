Auto-generated input/output reference: see [README.md](./README.md) (regenerated by `make docs`).

## What this module does

Attaches the full **Azure AI Hub Gateway** policy stack (vendored from
[Azure-Samples/ai-hub-gateway-solution-accelerator](https://github.com/Azure-Samples/ai-hub-gateway-solution-accelerator/tree/citadel-v1), MIT licence)
to an APIM instance produced by `modules/apim`. Additive — flip `enable_apim_policies = true`
to layer on top of the bare APIM.

## What gets deployed

- **APIs**: `universal-llm-api`, `azure-openai-api`, `ai-model-inference-api`, `unified-ai-api`,
  optional `openai-realtime-ws-api`, `document-intelligence-api{,-legacy}`,
  `azure-ai-search-{index,service}-api`, `translator-api`, `language-api`, `speech-api`,
  optional `weather-api` + Microsoft Learn MCP backend.
- **Backends**: one per `llm_backends` entry (managed-identity auth, circuit-breaker by default).
  Backend pools auto-created for any model supported by 2+ backends. Optional `foundry-embeddings`
  and `content-safety-backend`.
- **Policy fragments**: every `frag-*.xml` from citadel-v1. `set-backend-pools`,
  `get-available-models`, `metadata-config`, and `resolve-model-alias` have their dynamic C#
  splices generated from `llm_backends`.
- **Named values**: `uami-client-id`, `entra-auth`, `client-id`, `tenant-id`, `audience`,
  JWT-* set, `piiServiceUrl`/`piiServiceKey`, `contentSafetyServiceUrl`, AWS Bedrock placeholders.
- **Products**: `unified-ai-product` (key-auth); optional `llm-oauth-access` (JWT, gated on
  `enable_jwt_auth`).
- **Loggers**: App Insights + Azure Monitor. Optional Event Hub loggers for usage metering.

## Authentication

Backend auth is **managed identity only**. Pass the APIM identity's client ID via
`apim_identity_client_id` (UAMI). For system-assigned identity, leave it empty — the
clientId field is omitted and APIM uses its SA identity. Either way, grant the identity
`Cognitive Services OpenAI User` on each Foundry/OpenAI endpoint referenced in `llm_backends`.

## Required inputs

- `api_management_id`, `api_management_name`, `resource_group_name`
- `apim_identity_client_id` *(only if using UAMI; leave empty for SA identity)*
- `llm_backends` — at least one entry for anything meaningful to happen

## Usage-metering caveat

`frag-llm-usage.xml` and `frag-ai-usage.xml` `send-request` to the `usage-eventhub-logger`
/ `pii-usage-eventhub-logger`. Without `event_hub_logger_*` inputs those loggers aren't
created and the usage fragments fail at request time. Either provide Event Hub inputs or
accept that usage policies will return errors when policies fire.
